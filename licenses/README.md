# Third-party license corpus

Each directory under `licenses/` is one third-party component bundled by the
pylibseekdb wheel and the libseekdb SDK:

```text
licenses/<component>/
  METADATA.json
  <upstream license text>
```

`METADATA.json` records the component name, version, upstream source, packaging
form, license, modification state, license files, redistribution requirements,
and the evidence for the recorded version.

`METADATA.json` may also carry:

- `version_from`: an ordered list of build-time version sources. `build_requirement`
  reads the exact `name==x.y.z` pin from the `[build-system]` requires of
  `python/pyproject.toml` (the wheel build and the inventory share that pin);
  `python_package` asks `importlib.metadata` of the running interpreter.
- `version_check`: the dependency source or engine inventory entry the recorded
  version must still match.
- `tls_providers`: the TLS providers under which the component is linked. The
  staging step omits the record for other providers (Windows builds use schannel).
- `system_library`: layouts that provide the library themselves (`layouts`), the
  `packaged_as` text to record instead of the vendored form, and the SDK header
  (`version_from`) the version is read from. The dependency-source `version_check`
  is skipped for those layouts because the vendored copy is not compiled.

`scripts/stage-license-bundle.py` walks this directory, validates the metadata
against the pinned dependency sources, and renders the bindings layer of the
license bundle inside the SDK. `package.py` passes the packaging `--layout` and
`--tls-provider`; a wheel built without the SDK (`make wheel`,
`scripts/build-pylibseekdb-wheel.sh`) renders the bindings layer alone with
`--output` and `--version`. `--verify <bindings dir>` checks a rendered bundle
and is what `package.py` and `scripts/verify-wheel.sh` run on every wheel:

- `licenses/bindings/LICENSE` and `NOTICE` for the seekdb-bindings project;
- `licenses/bindings/THIRD_PARTY_COMPONENTS.md` and `.json` inventory;
- `licenses/bindings/REDISTRIBUTION.md`;
- `licenses/bindings/MANIFEST.sha256`;
- the component directories with the original license texts.

The verification requires every inventory license text and every required file
to be listed in a non-empty manifest with a matching digest, allows no
unlisted file, and rejects a `build_requirement` version that no longer matches
the pin.

The engine's own license bundle, generated by the seekdb source tree, stays
under `licenses/` next to `bindings/`. `licenses/README.md` explains the two
layers and points at both inventories.

The license texts must remain verbatim. Update the version and evidence fields
whenever the corresponding dependency changes; the build fails when the
recorded version no longer matches the dependency source.
